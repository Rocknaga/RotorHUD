# Rotorflight EdgeTX ウィジェット開発 — プロジェクト成果まとめ

## 概要
RadioMaster TX16S MK3(EdgeTX v2.12.0 "Queen Anne's Revenge")向けに、
Rotorflightのテレメトリを表示するColor LCDウィジェットを開発。
最終的な構成は「インストルメントクラスター型」:
Headspeedを中心に、Volt/Vcel(左)・Current/Bec volt(右)を配置し、
中段にGovernor/Flight/Profile、下部にBatteryバー、
フッターにThrottleとモデル情報を配置。

再接続検知、フライトログ(飛行後サマリー)、ARM警告の全画面表示、
画面遷移アニメーション、3種類のカラーテーマ(ラジオのウィジェット
設定から切替可能)なども実装済み。

## 今後similar開発で再利用できる技術的知見

### 1. EdgeTXフォントサイズの実測値(このファームウェア固有)
診断用ウィジェットで`lcd.sizeText()`を使い実測。推定と大きく異なった。

| フォント | 幅(1文字) | 高さ |
|---|---|---|
| デフォルト(0) | 12px | 27px |
| SMLSIZE | 10px | 23px |
| MIDSIZE | 19px | 42px |
| DBLSIZE | 25px | 55px |
| XXLSIZE | 51px | 93px |

→ **推測に頼らず、診断ウィジェットで`lcd.sizeText()`を叩いて実測するのが最も確実。**
（`lcd.sizeText`が無い機種向けにはグリッド付きテスト画像+実機写真での目視測定も有効）

### 2. `getTime()`の単位
1/10秒ではなく**1/100秒(10ms単位)**。誤ると計測系が10倍速/遅になる。

### 3. `lcd.drawBitmap`のscale引数
0〜1の比率ではなく**パーセント指定**(50=半分、100=等倍、200=倍)。
ただし`getBitmapSize()`が不正確な値を返すことがあり、動的スケール計算は
信頼性が低い。**確実なのは画像ファイル自体を表示先のサイズに事前リサイズし、
scale無しの等倍描画で使うこと。**

### 4. センサー名は「表示名」と「実際の内部名」が異なる
Rotorflight/EdgeTXのテレメトリセンサーは、設定画面等で見える名前と、
Lua`getFieldInfo()`で実際にマッチする名前が違うことが多い。
（例: 「Governor State」→実際は`Gov`、「Battery Charge Level」→`Bat%`、
「#1 ESC Capacity」→`EscC`、ESC温度→`Tesc`）
→ **実機のTelemetryセンサー一覧画面で全項目の正確な名前を一度に確認するのが最短。**

### 5. 開発の進め方(出戻りを減らすために有効だった方法)
- 診断専用の小さいウィジェットを作り、フォントサイズ・画像scale等を
  実機で一括測定してから本実装に反映する
- センサー名は1つずつ確認するのではなく、Telemetry一覧を丸ごと
  スクリーンショットで送ってもらい、まとめて反映する
- レイアウトの重なりバグは「推定値が違う」ことが原因であることが多く、
  フォント実測値を直すと連鎖的に解決するケースが多かった

## ファイル構成
- `main.lua` — ウィジェット本体
- `txbatt_*.png` — 送信機バッテリー残量アイコン(5段階)
- モデル画像(機体名と同名のPNG)を`/IMAGES`に配置する運用

## 現在の状態
機体画像表示は一時的に無効化中(`CONFIG.showModelImage = false`)。
再度有効化の指示があれば`true`に戻す。
